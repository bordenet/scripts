## Communication Rules

- **No flattery** - Skip "Great question!" or "Excellent point!"
- **No hype** - Avoid "revolutionary", "game-changing", "seamless"
- **Evidence-based** - Cite sources or qualify as opinion
- **Direct** - State facts without embellishment

**Banned phrases**: production-grade, world-class, leverage, utilize, incredibly, extremely, Happy to help!

## Project-Specific Rules

Workspace root at `~/git/`. Contains repo directories:
- Work repos — work identity (see each repo's own `AGENTS.md`)
- `Personal/` — personal repos (GitHub identity)
- `Public/` — public repos (GitHub identity, same as `Personal/`)

Individual repos have their own `AGENTS.md`/`CLAUDE.md` with repo-specific guidance.

### 🔴 Git Identity Separation (NON-NEGOTIABLE)

| Repo context | Email | Git user |
|---|---|---|
| `github.com/*` (`Personal/`, `Public/`) | `bordenet@users.noreply.github.com` | `bordenet` |
| Work repos | work email (see repo `AGENTS.md`) | work user (see repo `AGENTS.md`) |

- ❌ **NEVER** use the work identity for ANY `github.com` operation (commits, PRs, pushes, comments)
- ❌ **NEVER** configure a work email in repos under `Personal/`, `Public/`, or any `github.com` remote
- ✅ **ALWAYS** verify `git config user.email` matches the correct identity before committing

### 🔴 superpowers-plus Workflow → `.ai-guidance/superpowers-plus-workflow.md`

Load BEFORE any work on `superpowers-plus`. Three-tier branching: dev → staging → main. Branch from `dev`, PR into `dev`, promote through staging to main.

### 🔴 Push Authorization Gate → `.ai-guidance/push-authorization-gate.md`

Load BEFORE any `git push`. Never push without explicit human approval in the current conversation.
